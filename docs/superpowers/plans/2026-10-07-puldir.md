# puldir Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the puldir library: a profile generator that stands alone, an interrupt-driven multi-axis PUL/DIR core with stream mode, groups, homing and fault handling, the STM32 port, the `@` console, and a host test suite that proves every claim in the guidelines by counting fake pulses.

**Architecture:** Four layers, dependencies pointing one way. `motion_profile.{h,c}` is pure maths (a velocity-ceiling trapezoid with a moving-average jerk filter). The plan tick (1 kHz interrupt, float) re-bases the generator on the real pulse position each interval and publishes one fixed-point increment per axis. The pulse tick (50 kHz interrupt, integer only) accumulates the increments and toggles pins. A small port owns the two timers and the pins; main context only sends commands and reads state.

**Tech Stack:** C99, `gcc -Wall -Wextra` clean. Host tests: MSYS2 gcc (`/c/msys64/ucrt64/bin/gcc`, 15.2) from a bash shell, plain `assert`, one `test/run.sh`. Target: STM32G473 at 144 MHz, CubeMX + CMake, arm-none-eabi-gcc from the STM32CubeIDE bundle (used only in Task 11).

**Spec:** `docs/puldir-guidelines.md` (the design) and `docs/superpowers/specs/2026-10-07-puldir-design.md` (the review record; it wins when the two disagree).

## Plan decisions

The guidelines leave a few things open and get a few things wrong in detail. Each decision below is binding for the worker; the owner may overrule any of them.

**D1. Two generator helpers beyond 5.2.** Re-basing (5.4 step 2) and seeding the idle generator from the stream velocity (5.6) both rewrite the generator's private fields. The generator therefore gets `MotionProfile_rebase(p, shift, target)` and `MotionProfile_seed(p, pos, vel)`, tested bare, called by the axis.

**D2. Re-base shifts, it does not re-sync.** `rebase` subtracts the same integer `shift` from `pos` and `p_t` and sets `target` to the axis's target relative to the new origin, saturated to ±2²⁴. It never overwrites `pos` with the pulse position, so the sub-increment lag and any skipped direction tick stay in the next interval's `Δ`, as 5.4 step 4 requires.

**D3. Edges are hysteretic, not "integer part changed".** 5.3 step 4 pulses when the integer part of the pulse position changes. That rule is asymmetric. Moving up, the edge to count `k` comes when the position reaches `k`. Moving down, it comes when the position drops below `k+1`, a whole pulse early. Two consequences break the spec: a group member travelling downward emits its final pulse a pulse-time before the others (test 18 fails), and 5.4 step 5's "round away from zero" leaves a downward move one pulse past an integer target. So each axis keeps an `int32_t count` of pulses emitted and a 64-bit `edge`, the fixed-point position of the next edge in the current direction, `(count + dir) << 32`. A pulse is raised when the position reaches `edge` in the direction of travel; then `count += dir` and `edge += dir << 32`; a direction change recomputes `edge`. The cost is the same one 64-bit compare. Edges now fall at integer crossings in both directions, so test 10's "integer crossings" holds symmetrically, and dithering round an integer produces no chatter.

**D4. Axis targets are whole pulses.** `PulDir_moveTo` and `PulDir_moveBy` convert with `roundf(position · conversion)`, as cFlexyStepper did, and so does `PulDirGroup_moveTo`. Without this, "final pulses on the same tick" is impossible: an axis whose target is 1000.3 pulses emits its last edge at 1000.0, well before the end. Test 11's "fractional targets" are fractional in user units. Stops, jogs and streams are not rounded; they end wherever the ramp ends.

**D5. Increment sets latch at interval boundaries.** 5.3 step 1 latches a new set on the first tick after publication. The plan tick runs at a lower priority and its run time varies, so intervals would vary by a tick or more and the final pulse would move. Instead the pulse tick latches only when `ticks % n == 0` (`n = PULDIR_TICK_HZ / PULDIR_PLAN_HZ`), so every interval is exactly `n` ticks. The plan tick reads the pulse position and the tick counter together under the lock, predicts the position at the next boundary, `P_b = P + inc_live · (n − ticks % n)`, and computes `Δ` from `P_b`. Sets are double-buffered: the plan tick writes the buffer that is not published, then publishes it with one store, so no lock is needed between the ticks (test 16). If the plan tick misses a boundary, the pulse tick keeps the old set for one more interval and the next `Δ` corrects it.

**D6. The final edge is on the last tick of the done interval.** On the interval where the generator reports `done`, `inc = Δ / n` rounded away from zero lands the final edge exactly on tick `n` when `Δ > n·(n−1)` units of 2⁻³². Two rules guarantee that. While not done, if the profile position is within `M = n²` units of the target, the published end position is held `M` short of it on the side the axis approaches from. Every group member lands on the same plan interval because they share one profile. Together, every moving member's final rising edge falls on the same tick, and a one-pulse member's only edge is that edge.

**D7. Jog.** The generator's endless ceiling is `sign(speed) · min(|speed|, vmax)`, so a lowered speed limit ramps a jog down. `PulDir_jog(0)` is `PulDir_stop`. `PulDir_jog` refuses non-finite speeds and speeds at or above the tick ceiling.

**D8. The trapezoid parity requirement is tested against the analytic trapezoid.** cFlexyStepper's recurrence is a first-order approximation of the same trapezoid that deviates by a few percent at low pulse counts (firmware handoff note, section 10). Test 2 compares time and peak with the analytic trapezoid instead.

**D9. Test isolation.** The axis library has file-scope state: the axis table, the tick counter and the increment sets. `test_puldir` takes a case name and runs one case per process, and `run.sh` loops over the names it prints for `list`. Test 22 needs the tick counter to start near its wrap. That comes from a config macro, `PULDIR_TICK_START` (default 0), set by a third build of the suite. The library has no test-only functions.

**D10. The bench gate.** Section 9 says the bench step (Task 11) comes before any planning code (Task 12 on). The owner asked for the work to continue unattended, and the bench needs the owner, a scope and CubeMX. So the worker writes the port, compiles it against the firmware's HAL, writes the bench checklist and carries on with the host tasks. The owner runs the bench. If the measurements rule out a tick rate, only `PULDIR_TICK_HZ` and the port change; the plan maths is independent of the tick rate.

**D11. Stream catch-up per axis.** 5.6 says the caller may override `T_CATCHUP` per axis, and 6.1 has no function for it. The plan adds `bool PulDir_setStreamCatchup(PulDir*, uint32_t ms)`. It refuses values below five plan intervals and refuses while the axis is in STREAM.

**D12. Fault latch does not release the drive.** 2.2 says "halt on latch". cFlexyStepper also disabled the drive. The firmware handoff note warns that a released lean axis drops the plate. puldir halts and leaves the enable pin alone.

---

**D13. The landing rule tests the distance against one decel step.** 5.2 step 4 lands when `|rem| ≤ |v_t|·dt` with the new `v_t`. Following the ceiling exactly, the remaining distance before a step is `v²/(2·dmax) + v·dt`, which is always larger than `v·dt`, so that rule only fires once rounding drives the velocity to zero. A simulation of the 9-unit move of test 2 lands four calls late that way. The plan's rule: land when `|rem| ≤ dmax·dt²`, `rem` has the sign of the previous `v_t` (or either is zero), and going from the previous `v_t` to `rem/dt` respects the step rule (a shrink of at most `dmax·dt`, a growth of at most `amax·dt`). Following the ceiling, that landing step changes velocity by at most `dmax·dt/2`, so it is no exception to any limit.

**D14. `MotionProfile_init` returns `bool`.** It refuses a non-finite `pos` and a `dt` outside 0.25 ms to 10 ms. The lower bound is 0.25 ms rather than 5.2's 1 ms because 5.4 allows `PULDIR_PLAN_HZ` of 2 kHz, and the axis initialises its profile at the plan interval. A fresh profile is `done` at `pos` with limits `{1, 1, 1, 0}`.

**D15. The pin type comes from `puldir_pin.h`.** The core must know `puldir_pin_t` to store pins in `PulDir`, yet the port defines it. Each port directory provides a `puldir_pin.h` defining `puldir_pin_t` and nothing else: `port/stm32/puldir_pin.h` (`{ GPIO_TypeDef* port; uint16_t pin; }`, including `main.h`) and `test/puldir_pin.h` (`{ uint8_t id; }`). The build puts exactly one port directory on the include path. `puldir_port.h` includes it.

**D16. Setup functions that can be handed invalid input return `bool`.** 6.1 declares `PulDir_setConversion`, `PulDir_setDefaults`, `PulDir_setHoming` and `PulDir_register` as `void`, which leaves "refuse, do not clamp" nowhere to report. They return `bool` and raise a refusal like every other call. `PulDir_setConversion` refuses zero, negative and non-finite values; the direction sense belongs to `dir_inverted`.

**D17. Commands are requests the plan tick applies.** A main-context call validates its arguments, then under `port_lock` writes them and a request bit into the axis, and sets at once whatever the caller may read back straight away: `isMoving`, the mode, the target, the enable pin. The plan tick applies the generator calls at the start of its next run. That keeps every locked section to a handful of stores. The generator's `halt` alone clears up to 256 taps, which would blow the one-microsecond budget of 5.9. `PulDir_halt` also zeroes the axis's live and published increments under the lock, so no pulse follows the tick it is called in.

**D18. The position getter reads the emitted count.** `PulDir_position` returns `count / conversion`, where `count` is the pulse tick's count of edges (D3). That is what the drive has been told. `PulDir_setPosition` sets `count`, the pulse position and `edge` together under the lock, which it may because it is accepted only in IDLE.

**D19. `isMoving` clears two plan ticks after the done interval is published.** The done interval runs during the interval after publication, and its final pulse is lowered on the first tick of the interval after that. The plan tick therefore counts two runs after publishing the done increment, checks the pulse pin is low, and only then sets the mode to IDLE, clears `moving` and raises the landed event.

**D20. Library-internal declarations live in `puldir_internal.h`.** Functions and data shared between the library's own files (the axis table, the increment sets, the event helpers) are declared there, never in `puldir.h`.

## Generator tasks (section 9 steps 1 and 2)

All generator tests live in `test/test_motion_profile.c`: one executable, one function per test, called in order from `main`, each printing `ok <name>`. A shared checker runs after every `advance` in every test and asserts the limits of 5.2, so every later test checks the limits for free:

```c
/* After every advance: velocity, acceleration and (with jerk) jerk bounds.
 * The tolerance absorbs float rounding, not design slack. */
static int g_vmax_relaxed;   /* set by tests that lower vmax or retarget infeasibly */

static void check_step(const MotionProfile* p, float vel0, float acc0)
{
    const float tol = 1e-4f;
    const MotionLimits L = p->lim;
    const float dv = p->vel - vel0;
    const bool speeding_up = fabsf(p->vel) > fabsf(vel0);
    const float bound = speeding_up ? L.amax : L.dmax;

    if (!g_vmax_relaxed)
        assert(fabsf(p->vel) <= L.vmax * (1.0f + tol));
    assert(fabsf(dv) <= bound * p->dt * (1.0f + tol) + 1e-6f);
    if (L.jmax > 0.0f)
        assert(fabsf(p->acc - acc0) <= L.jmax * p->dt * (1.0f + tol) + 1e-3f);
}

static void step(MotionProfile* p)
{
    const float v0 = p->vel, a0 = p->acc;
    MotionProfile_advance(p);
    check_step(p, v0, a0);
}
```

A velocity that crosses zero within one call counts as a shrink to zero followed by a growth, and the checker accepts it when `|dv| ≤ max(amax, dmax)·dt`. Only the landing call and the jerk filter's output can do that.

```c
/* Motion profile generator: an acceleration-limited online trapezoid whose
 * velocity passes through a moving-average jerk filter. Pure maths, no
 * statics, unit-agnostic. Section 5.2 of docs/puldir-guidelines.md. */
#ifndef MOTION_PROFILE_H
#define MOTION_PROFILE_H

#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

#ifndef MOTION_PROFILE_MAX_TAPS
#define MOTION_PROFILE_MAX_TAPS 256       /* raise for softer jerk */
#endif

typedef struct {
    float vmax, amax, dmax, jmax;         /* jmax 0 = unlimited (trapezoid) */
} MotionLimits;

typedef struct {
    float dt;                             /* seconds per advance, fixed at init */
    float pos, vel, acc;                  /* the output: filtered, caller's units */
    float target;
    bool  endless;                        /* run at a speed, no target */
    bool  stopping;                       /* stop as soon as the ramps allow */
    bool  landed;                         /* the trapezoid is at rest; the ring may still drain */
    bool  done;                           /* at target with vel == 0.0f exactly */
    MotionLimits lim;
    /* private */
    float    p_t, v_t;                    /* the trapezoid's own position and velocity */
    float    speed;                       /* endless speed, signed */
    float    taps[MOTION_PROFILE_MAX_TAPS];
    uint16_t n, head;                     /* window length; next slot to overwrite */
    uint16_t drain;                       /* calls since landing, up to n */
    float    sum;
} MotionProfile;

bool  MotionProfile_init(MotionProfile*, float pos, float dt);
bool  MotionProfile_setLimits(MotionProfile*, MotionLimits);
bool  MotionProfile_setTarget(MotionProfile*, float target);
bool  MotionProfile_setEndless(MotionProfile*, float speed);
void  MotionProfile_stop(MotionProfile*);
void  MotionProfile_halt(MotionProfile*);
bool  MotionProfile_setPosition(MotionProfile*, float pos);
void  MotionProfile_advance(MotionProfile*);
float MotionProfile_stopDistance(const MotionProfile*);
/* For the axis (D1): shift the origin by a whole number, set the target relative to it. */
void  MotionProfile_rebase(MotionProfile*, float shift, float target);
/* For the axis (D1): from rest, put the profile in motion at vel through pos, ring full of vel. */
bool  MotionProfile_seed(MotionProfile*, float pos, float vel);
/* The smallest jerk whose window fits MOTION_PROFILE_MAX_TAPS, for refusal messages. */
float MotionProfile_minJerk(float amax, float dmax, float dt);

#ifdef __cplusplus
}
#endif
#endif
```

```c
static Run run_to_done(MotionProfile* p, int max_calls)
```

- [ ] **Step 3: Implement `setTarget` and the trapezoid half of `advance`.** `setTarget` refuses a non-finite target; otherwise it sets `target`, clears `endless`, `stopping`, `landed` and `done`, sets `drain = 0`, and returns true. The trapezoid is this code, verbatim. The landing test comes first and uses the previous `v_t` (D13):

```c
/* Move v toward vc by at most up when |v| grows and down when it shrinks.
 * Never crosses zero in one call: it lands on zero and reverses next call. */
static float toward(float v, float vc, float up, float down)
{
    const bool same_dir = (v > 0.0f) == (vc > 0.0f);
    if (vc != 0.0f && (v == 0.0f || (same_dir && fabsf(vc) > fabsf(v))))
        return copysignf(fminf(fabsf(v) + up, fabsf(vc)), vc);
    const float floor_ = (same_dir && v != 0.0f) ? fabsf(vc) : 0.0f;
    return copysignf(fmaxf(fabsf(v) - down, floor_), v);
}

/* One step of the trapezoid. Returns the velocity used over this step. */
static float trapezoid(MotionProfile* p)
{
    const MotionLimits L = p->lim;
    const float dt = p->dt, dd = L.dmax * dt;
    if (p->landed)
        return 0.0f;

    const float rem = p->target - p->p_t;
    if (!p->endless && !p->stopping) {
        /* Landing: the rest of the way in one step, within the step rule (D13). */
        const float u = rem / dt, v = p->v_t;
        const bool same = v == 0.0f || rem == 0.0f || (u > 0.0f) == (v > 0.0f);
        const bool fits = fabsf(u) <= fabsf(v) ? fabsf(v) - fabsf(u) <= dd
                                               : fabsf(u) - fabsf(v) <= L.amax * dt;
        if (fabsf(rem) <= dd * dt && same && fits) {
            p->p_t = p->target;           /* the one place p_t is assigned */
            p->v_t = 0.0f;
            p->landed = true;
            return u;
        }
    }

    float vc;
    if (p->stopping)
        vc = 0.0f;
    else if (p->endless)
        vc = copysignf(fminf(fabsf(p->speed), L.vmax), p->speed);
    else /* the discrete ceiling: do not simplify to sqrtf(2*dmax*|rem|) */
        vc = copysignf(fminf(L.vmax, sqrtf(dd * dd + 2.0f * L.dmax * fabsf(rem)) - dd), rem);

    p->v_t = toward(p->v_t, vc, L.amax * dt, dd);
    p->p_t += p->v_t * dt;
    if (p->stopping && p->v_t == 0.0f) {
        p->target = p->p_t;
        p->stopping = false;
        p->landed = true;
    }
    return p->v_t;
}
```

```c
void MotionProfile_advance(MotionProfile* p)
{
    if (p->done)
        return;
    const bool was_landed = p->landed;
    const float u = trapezoid(p);
    const float vel0 = p->vel;
    p->vel = u;
    p->pos = p->p_t;
    p->acc = (p->vel - vel0) / p->dt;
    if (was_landed && ++p->drain >= p->n)
        finish(p);
}
```

In the single-tap case `done` comes on the call after landing, whose output is `vel = 0`. Task 6 replaces the three output lines with the filter.

```c
void MotionProfile_rebase(MotionProfile* p, float shift, float target)
{
    p->pos -= shift;
    p->p_t -= shift;
    if (p->landed || p->endless || p->stopping)
        p->target -= shift;
    else
        p->target = target;
}

bool MotionProfile_seed(MotionProfile* p, float pos, float vel)
{
    if (!p->done || !isfinite(pos) || !isfinite(vel))
        return false;
    p->pos = p->p_t = p->target = pos;
    p->v_t = p->vel = p->speed = vel;
    p->acc = 0.0f;
    for (uint16_t i = 0; i < p->n; i++)

    p->head = 0;
    p->endless = true;
    p->stopping = p->landed = p->done = false;
    p->drain = 0;
    return true;
}
```

```c
PulDir* puldir_axes[PULDIR_MAX_AXES];
uint8_t puldir_naxes;

static PulDirInc sets[2][PULDIR_MAX_AXES];
static PulDirInc live[PULDIR_MAX_AXES];
static volatile uint8_t pub;            /* index of the last published set */
static volatile uint8_t seq, latched;   /* publish count; publish count last latched */
static volatile uint32_t ticks = PULDIR_TICK_START;
static volatile uint32_t left = PULDIR_TICKS_PER_PLAN;   /* ticks left in this interval */
static volatile uint32_t overruns;

static void write_pul(PulDir* a, bool active) { port_pin_write(a->pul, active != a->pul_active_low); }
static void write_dir(PulDir* a, int8_t d)    { port_pin_write(a->dir, (d > 0) != a->dir_inverted); }

void puldir_pulse_tick(bool overrun)
{
    if (overrun)
        overruns++;
    if (left == PULDIR_TICKS_PER_PLAN && latched != seq) {   /* a boundary: latch the whole set */
        const PulDirInc* s = sets[pub];
        for (uint8_t i = 0; i < puldir_naxes; i++)
            live[i] = s[i];
        latched = seq;
    }
    for (uint8_t i = 0; i < puldir_naxes; i++) {
        PulDir* a = puldir_axes[i];
        bool edge = false;
        if (a->pul_high) {
            write_pul(a, false);
            a->pul_high = false;
            edge = true;
        }
        const int8_t d = live[i].dir;
        if (d != a->dir_now) {           /* never on a tick with a pulse edge */
            if (!edge) {
                write_dir(a, d);
                a->dir_now = d;
                a->edge = ((uint64_t)(uint32_t)(a->count + d)) << 32;
            }
            continue;
        }
        a->P += (uint64_t)(int64_t)live[i].inc;
        const int64_t past = (int64_t)(a->P - a->edge);
        if (d > 0 ? past >= 0 : past <= 0) {
            write_pul(a, true);
            a->pul_high = true;
            a->count += d;
            a->edge += (uint64_t)(int64_t)d << 32;
        }
    }
    ticks++;
    if (--left == 0)
        left = PULDIR_TICKS_PER_PLAN;
}
```

  The other functions: `puldir_shadow` returns `sets[pub ^ 1]`; `puldir_publish` does `pub ^= 1; seq++;` (the plan tick is the only caller, so the two stores cannot interleave with another publish, and the pulse tick reads `pub` only at a boundary). `puldir_kill(slot)` zeroes `live[slot].inc` and `sets[pub][slot].inc`. `puldir_left` returns `left`; `puldir_live_inc` returns `live[slot].inc`.

  At start every axis's `live` and `sets` entries must have `dir = +1`, matching `dir_now` and the parked direction pin. `PulDir_register` sets them.

  `PulDir_overruns` returns `overruns`; `PulDir_ticks` returns `ticks`.

```c
#define N  PULDIR_TICKS_PER_PLAN
#define DT (1.0f / (float)PULDIR_PLAN_HZ)
#define M  ((int64_t)N * N)                      /* D6 margin, in 2^-32 pulse */

static int64_t to_fix(float pulses) { return (int64_t)(pulses * 4294967296.0f); }
static int32_t sat(int64_t q)
{   /* the speed cap keeps cruise below this; only a catch-up can reach it */
    return q > PULDIR_INC_MAX ? PULDIR_INC_MAX : q < -PULDIR_INC_MAX ? -PULDIR_INC_MAX : (int32_t)q;
}
static int32_t div_trunc(int64_t d) { return sat(d / N); }
static int32_t div_away(int64_t d)
{
    int64_t q = d / N;
    if (q * N != d) q += d > 0 ? 1 : -1;
    return sat(q);
}

typedef struct { uint64_t P; int32_t count, inc; } Snap;

void puldir_plan_tick(void)
{
    Snap s[PULDIR_MAX_AXES];
    uint32_t left;
    port_lock();                                  /* one consistent instant for every axis */
    left = puldir_left();
    for (uint8_t i = 0; i < puldir_naxes; i++) {
        s[i].P = puldir_axes[i]->P;
        s[i].count = puldir_axes[i]->count;
        s[i].inc = puldir_live_inc(i);
    }
    port_unlock();

    PulDirInc* out = puldir_shadow();
    for (uint8_t i = 0; i < puldir_naxes; i++) {
        const uint64_t Pb = s[i].P + (uint64_t)((int64_t)s[i].inc * left);   /* D5 prediction */
        run_axis(puldir_axes[i], &out[i], Pb, s[i].count);
    }
    puldir_publish();
}
```

- E2 (Task 5 review): `toward()` never sheds less than the decel step to rounding (nextafterf), and the trapezoid position is Kahan-summed (p_c). - E3 (Task 6): running filter sum is Kahan-compensated (sum_c); jerk tolerance in the checker is a few acc quanta.
- E4 (Task 6/7): `done` arrives n+1 calls after landing (not n). Forcing acc = 0 on the n-th call broke the jerk bound when amax < 0.41·dmax.
- E5 (Task 6/7): filtered pos = p_t − lag (lag = weighted ring), not integrated; integration drifted 1 ulp past targets.
- E6 (Task 7): dt-independence tolerance includes the windows' extra calls.
- E7 (Task 8 review): the drain after landing is O(1) per call: on the first drain call the ring is converted in place to prefix sums; setTarget/setEndless mid-drain convert back. Worst single call is one O(n) pass (~2.6k flops at n = 256). `#error` under -ffast-math (compensated sums need strict float).
- E8: generator random-move large batches cut to 300 moves each to keep run.sh near 4 s.
- E9 (Task 10 review): pulse-tick hot state (P, edge, count, dir_now, pul_high, pins, live inc) lives in a static array in puldir_pulse.c, not in PulDir; others use internal accessors (snapshot under lock, pul_high, datum set). Count arithmetic is unsigned (defined wrap). Register refuses after start. `puldir_left()` returns N (not 0) at a boundary.
- E10: PulDir_init sets edge = one pulse (else the first increment fires an edge). STM32 port_lock must be harmless before bind (puldir_refuse locks, and register can refuse before start).
- E11 (Task 12): the boundary prediction uses ahead = left % N (D5's formula had an off-by-one at phase 0: the set latches on the very next tick). Superseded by E13 for the final edge.
- E12 (Task 11 review): the STM32 port zeroes both timer counters and starts the pulse timer then the plan timer, so the plan tick runs just after each boundary. Bench measures jitter on the ISR marker or at a tick-dividing rate.
- E13 (Task 12 review): the final increment (rounded away) is published on arrival (the first call the generator has landed with its end on the target), not on `done`; settle calls keep steering toward the target if the count would end short (late or overwritten set); IDLE needs settle elapsed, done and the pin low. Every edge, the last included, is within ±1 tick of the generator's crossing.
- E14 (Task 12 review): on an interval that reverses direction, the pulse position may trail the aim by up to 2·|inc| (direction write plus a deferred tick); guideline 5.4's "one increment" holds elsewhere.
- E15 (Task 12 review): setConversion is IDLE-only and keeps limits and defaults fixed in pulses (user-unit values rescale), as cFlexyStepper did; it is never refused for rate or taps.
- E16 (Task 13): the generator's landing call keeps v_t = rem/dt (the velocity it actually moved at) and zeroes it on the next landed call; stopDistance ignores v_t once landed. Setting v_t = 0 on the landing call let a reversing command on the next call exceed the step limit (27.45 vs 20).
- E17 (Task 13): `arrived` and `settle` are cleared whenever the generator gets a new goal (target, endless, halt; stream and homing must do the same). The fault latch in the plan tick must halt directly, not through REQ_HALT.
- E18 (Task 14): test 12's 2-pulse bound is not met at the default T_CATCHUP = 50 ms: the first-order hold lags at a·age·T_c (worst 5.5-6.3 pulses at 200 Hz, 3.4-3.7 at 1 kHz on a sine peaking at 27,600 pulses/s², about 3x the first machine's accel). The tests assert the measured bounds with the cause written in; a 1 kHz run at T_c = 5 ms meets 2 pulses (1.26). Default kept at 50 ms (stable for any stream rate the library accepts); owner to decide: shorter default, per-axis tuning, or a second-order hold (not in 5.6).
- E19 (Task 15): arrival/D6/settle logic is shared as puldir_steer() by axes and group members. Group arrival = s landed on its target; members aim at start + Δ·s in fixed point. Group start waits for every member's pin direction. PulDirGroup_init returns bool; PulDir_stop on a member is refused (members refuse all but halt); group moveTo needs members not moving. Test 18's count bound is one pulse plus N units (the count trails the pulse position by up to one pulse). Group halt is puldir_group_halt(g, shadow), callable under the lock from main or the plan tick.
- E20 (Task 16): every accepted motion command wakes the drive under the lock; the plan tick holds until enable_ms (ena_wait flag, wrap-safe). Fault pins are sampled before the snapshot lock; a latch halts directly in the plan tick (group: puldir_group_halt under the lock, faulted set). A homing timeout halts (5.8 and 2.2 win over 5.5's STOPPING row); stop during homing ramps down and ends the run. Homing timeouts apply to the three moving phases; delays are PULDIR_HOMING_DELAY_MS. setDelays returns bool (D16). enable() refused without an enable pin.
- E21 (Task 15 review): group travel above 2^24 pulses is refused (float s quantisation); limit setters on a GROUP member are refused (the path profile owns the limits); groups need static storage.
- E22 (Task 16 review): a fault halt marks every axis it halted so auto-release skips it until its next command (D12). After a clear pulse the latch drops only once the alarm input reads inactive; until then motion stays refused and the count does not grow. The homing moving phases run at the homing speed (as the old jog did); a timeout or homeStop leaves that speed as the limit, a finished run leaves the defaults. enable(false) with the pulse pin high is completed by the plan tick.
- E23 (Task 17): console helpers are shared through puldir_internal.h; log lines are up to 128 bytes. Bad numbers are refused ("bad argument"); K on an axis without an enable pin only halts.
- E24 (final review): an overrun is logged once per new batch ("pulse tick overrun, total N") by the first axis loop that can log. homeStart saves the limits in force; every exit but a homed run puts them back (supersedes E22's "leaves that speed as the limit"); a homing stop whose restored jerk window does not fit the one in flight is applied once the generator rests. The limit setters, setDefaults and restoreDefaults are refused in HOMING as in GROUP. PulDir_init returns bool and refuses a NULL name or one over 15 characters.
- E25 (final review): the STM32 port presets the pulse counter to its auto-reload value in port_start. The G4 HAL starts a timer without a pending update, so with both counters at zero every plan tick ran one pulse tick before its latch. Unverified on hardware: bench step 6 checks it.
- E26 (timer contract): the application attaches two timers already counting at 1 MHz (PulDir_stm32_attachPulseTimer, attachPlanTimer); port_start writes their ARR from PULDIR_PULSE_US (the build knob; PULDIR_TICK_HZ is derived) and PULDIR_PLAN_HZ, and the raw IRQ entries return at once with UIF clear, so shared vectors are safe. Both counters now start one count before their first update: at a common 1 MHz count, E25's plan counter at 0 would put each plan tick one count, less the start skew, before its latch.
- E27 (runtime timing): the pulse and plan periods are runtime arguments of the timer attach calls (PulDir_stm32_attachPulseTimer(htim, irqn, pulse_us), attachPlanTimer(htim, irqn, plan_us)), which come first, and PulDir_init(axis, name, pulses_per_unit) checks their ratio, fixes them, takes the conversion (setConversion is gone) and logs the axis's max speed and resolution in user units. E26's build macros PULDIR_PULSE_US and PULDIR_PLAN_HZ are superseded; its timer phasing stands.
- E28 (simplification): one routine, puldir_halt_locked (under the lock, from main or the plan tick), halts for PulDir_halt, the fault latch and a homing timeout, with PulDir_stop sharing its limit restore; service() halts a non-member itself and re-reads its snapshot, and run_axis applies the halt's REQ_HALT and REQ_LIMITS in the same run (E17's direct halt stands); a phase timeout halts the generator and restores its limits on its own tick, and the requests it leaves repeat harmlessly on the next; halt_now and home_unwind are gone. MotionProfile_checkLimits is the one limit check (setLimits, apply_limits and the group's path limits ask it), MotionProfile_minJerk is the plain quotient, printed rounded up by 16 ulps so the figure typed back fits (jerk_floor's float-boundary search is gone), PulDirPulse and puldir_pul_high fold into PulDirSnap through puldir_pulse_read(slot, ahead, out) (E9's accessor list reads so), and motion_check replaces motion_refused and runs only under the lock, so a bad argument on a faulted axis is now refused as ARG. port_pin_init_output and port_pin_init_input leave the port contract (5.10 and E9 superseded on that point): the attach calls park the outputs with port_pin_write before PulDir_start, pin modes being the application's business.
- E29 (external review): a datum set before registration carries through it: puldir_pulse_add takes the slot's count from the axis's target (whole in IDLE) and PulDir_position reads the target's whole pulses on an unregistered axis; moveTo, moveBy, jog, streamBegin and homeStart refuse an unregistered axis (PULDIR_R_UNREGISTERED), since the ticks cannot run before start and start needs registration. A published set carries its due tick (now + ahead, the boundary the snapshot aimed at) and the pulse tick latches a pending set at a boundary or at any tick at or past its due tick, so a set published late runs the rest of its interval instead of a whole one later and the next plan tick corrects the shortfall from the real position (latched a whole boundary late, a 301-pulse move ended at 310: the settle branch republished the remainder and both sets ran, and going IDLE wrote the target over). The axes still land exactly for a set at most two ticks late, at any speed; k ticks late at an approach increment of i pulses per tick, one extra pulse past the target appears once k·i reaches a pulse (three ticks late above a third of a pulse per tick). A late latch is a plan-tick timing fault: PulDir_lateSets counts it, PulDir_loop logs each new batch ("plan tick late, total N"), and bench step 6 reads it as the phase check.
- E30 (simplification): once the trapezoid has landed the jerk filter drains by pushing the zeros it returns through the normal push; drain_step, the in-place prefix sums and their conversion back in setTarget and setEndless, and the `same` field are gone (E7 superseded). The running Kahan sums leave a sub-ulp residue which, at a target of 0, put the output a hair past it on the drain's last calls, so both sums are exactly zero once every tap is, and while landed the lag may only shrink toward zero once the whole ring shares a sign (an O(1) run counter in push, zeros extending the run, says when): for a one-signed ring that is what exact arithmetic gives, so the rule only removes rounding. A ring of both signs at landing (a jog, then a target at or just behind the position) drains unclamped, since its exact lag legitimately carries the output on before it returns; clamped, pos stood still while vel was not zero, an unfiltered stop (review). finish snaps the rest as before.
- E31 (external review): the guidelines' 5.2 claim that the window `(amax + dmax) / (jmax·dt)` keeps `(amax + dmax) / (n·dt) ≤ jmax` was wrong for reversals: the filtered jerk is the difference of two trapezoid accelerations one window apart, and a reversal puts +amax and -amax (or the larger ramp both ways) there, a span of 2·max(amax, dmax). With {15, 90, 20, 550} at dt 0.001 the jerk reached 900. The window, the frozen-window check and minJerk now use 2·max(amax, dmax); symmetric limits are unaffected.
- E32 (external review): a live limit change was checked against the frozen window alone, but the ring still holds motion made under the limits being replaced: {15, 30, 30, 300} accelerating at 30, then setLimits({15, 1, 1, 10}) was accepted and the next call's jerk was 144 against 10. In flight, new limits are accepted only if (max(amax', dmax') + A) / (jmax'·dt) ≤ n, A being the larger of max(amax', dmax') and the largest max(amax, dmax) of any limits in force during the last n calls (hist_acc and hist_left, O(1): set on an accepted in-flight change, cleared n calls later or with the ring); when the new limits are the larger this is E31's frozen-window test, so it is the one in-flight expression. Lowering amax or dmax under the same jerk, and raising the jerk, still fit; a lowered jerk or a raised ramp beyond the slack is still refused. MotionProfile_checkLimits takes the profile; apply_limits asks it once, under the lock (about 100 cycles), and the group asks on its own profile, at rest at moveTo. hist_left restarts on every accepted change, so a set replaced twice within a window is kept up to 2n − 1 calls: conservative, never unsafe. On the landing call v_t still holds the landing step (E16) and the next call zeroes it, a step the new limits do not bound, so it counts as an acceleration of its own in the check (review): a change issued on a landing tick that does not fit it is refused until the next plan tick; |v_t|/dt is at most the old dmax, within the history, so the test stays exact.
- E33 (owner's choice, simplicity): log and reply lines are formatted with `snprintf` into a PULDIR_LINE buffer, floats passed as `(double)x` with `%.4f`; the integer-only formatter (puldir_put, puldir_put_uint, puldir_put_num, puldir_head) is gone. The guidelines' "no printf" rule (5.9) is relaxed for main-context logging only: the ticks still format nothing. A newlib-nano build links float printf (`-u _printf_float`). The jerk floor is still printed rounded up, `ceilf(v · 1e4 · (1 + 16 FLT_EPSILON)) / 1e4` in float, so the figure typed back fits. newlib's `%f` allocates from the heap on its first use and needs roughly 1 KB of stack; logging happens only in main context, so both costs fall on the main loop, never on the interrupts, and E33 relaxes the guidelines' "no allocation" rule (5.9) on the same terms as "no printf". Two log texts changed at the edges: inf and values of 1e14 or more now print in full instead of `1e14+`, and the last of the four decimals can round differently from the old formatter, since snprintf rounds the exact value where it rounded in float.
- E34 (refactor, no behaviour change): enable, fault, homing and stream each have their own struct, embedded by value in PulDir as `enable`, `fault`, `home` and `stream`, and their own file. puldir_enable.c owns the enable pin, the enable delay, the deferred disable and auto-release; puldir_fault.c the alarm and clear pins, the debounce, the latch and the clear pulse (the halt a latch causes stays in the plan tick); puldir_homing.c the homing configuration, the phases, the saved limits and `homed`; puldir_stream.c the setpoint, the hold, the catch-up and the timeout. Each module's header declares its struct for puldir.h and its internal functions for puldir_internal.h only; the core calls their plan-tick services in the order the code ran before, and the public PulDir_* API is unchanged. Each module's state is written only by its own file: the core goes through named calls (puldir_enable_hold, puldir_enable_delaying, puldir_fault_latched, puldir_home_cancel, puldir_home_lose_datum, puldir_home_hold, puldir_stream_halt, puldir_stream_defaults). The reads left outside the modules are plain reads of public status for reporting: PulDir_status reads `enable.enabled` and `enable.attached`, PulDir_loop reads `fault.count` and `home.fail` for its lines, and the console reads `fault.count`, `fault.last_tick`, `home.state`, `home.fail` and `enable.attached` (the K verb releases only an axis with an enable pin).
- E35 (refactor, no behaviour change): a standalone drive/ split of the enable and fault modules was tried and reverted: it added code, its standalone use was theoretical, and it exposed lock-bypassing calls to applications through puldir.h. Each setting now lives in its module's header (the fault durations in puldir_fault.h, the homing delay in puldir_homing.h, the stream's two in puldir_stream.h, PULDIR_MAX_GROUPS in puldir_group.h), and groups have their own header, puldir_group.h, which puldir.h includes after PulDir.
