puldir Library Map

puldir drives several PUL/DIR motor drives from one microcontroller. Every pulse comes from a timer interrupt; the main loop only sends commands and reads state. Each tab below covers one module: what it does, what it uses, its settings, its types, its calls and its flow.

cPulDir · branch implement-puldir @ 42434ca · examples use the README timing: pulse_us = 20 (a 50 kHz pulse tick), plan_us = 1000 (a 1 kHz plan tick), so N = 50 pulse ticks per plan interval

00Overview

Everything in puldir runs in one of three places. Your main loop calls the API. A timer interrupt every plan_us, the plan tick, does all the maths. A faster timer interrupt every pulse_us, the pulse tick, only adds integers and writes pins. Commands flow down, measurements flow back up, and each crossing has one fixed mechanism. The core is plain C99 with no HAL; the STM32 port and the host test port each supply the pin type and five functions.

Main context

your loop · any rate · lowest priority

  • Setup in a fixed order (below). Every call returns a result; refusals are logged.
  • Commands check their arguments, then store a request bit under the lock (D17). They never run the generator.
  • Getters read one value, under the lock where it is wider than a word.
  • PulDir_loop prints what happened. Calling it often or never changes no motion.

Plan tick

plan timer · plan_us = 1000, a 1 kHz tick · below the pulse tick

  • Samples fault pins, snapshots every axis, services enable and fault.
  • Runs every group, then applies each axis's requests and runs its mode: profile, stream or homing.
  • Publishes one fixed-point increment and direction per axis.
  • All float maths lives here.

Pulse tick

pulse timer · pulse_us = 20, a 50 kHz tick · highest priority

  • Latches a new increment set at a boundary, or at once if the set is past due.
  • Per axis: lowers last tick's pulse, writes a direction change on an edge-free tick, adds the increment, raises a pulse at each whole-pulse crossing.
  • Integer only. A pulse is one tick wide (20 µs here).

cSetup order

The order the library requires. Init refuses without the timers, register refuses an axis without init and pins or after start, and a group refuses members that are not registered.

  1. mainAttach both timers with their periods in µs: PulDir_stm32_attachPulseTimer(&htim, irqn, pulse_us) and PulDir_stm32_attachPlanTimer(&htim, irqn, plan_us). On the host, fake_attach(pulse_us, plan_us).
  2. mainPulDir_attachLogger(fn), so init can log.
  3. mainPulDir_init(&ax, "tilt", 280.0f) per axis, with the conversion in pulses per unit. The first accepted init fixes the timing and logs [tilt] max speed 89.2857 units/s, resolution 0.0036 units/pulse (pulse 20 us, plan 1000 us).
  4. mainPins: PulDir_attachPins, and optionally PulDir_attachEnable, PulDir_attachFault, PulDir_attachFaultClear. Each parks its outputs inactive.
  5. mainDefaults and delays: PulDir_setDefaults, PulDir_setDelays, PulDir_setAutoRelease, and PulDir_setStreamCatchup if the default 50 ms does not suit.
  6. mainHoming: PulDir_setHoming, if the axis homes.
  7. mainPulDir_register for each axis.
  8. mainPulDirGroup_init for each group, with static storage.
  9. mainPulDir_start: fixes the timing if no init did, then port_start writes both periods and starts the timers. From here the ticks run.

01Generator motion_profile.h · motion_profile.c

1What it does

A trapezoid computed one step at a time, whose velocity passes through a moving-average filter of up to MOTION_PROFILE_MAX_TAPS samples to limit jerk. Its four settings are not alike: speed, acceleration and deceleration are what a move uses (a short move never reaches the speed), while jerk is a bound the filtered motion stays under (an ordinary move peaks near half of it, since the window is sized for a reversal, E31). It takes a target, an endless speed, a stop or a halt at any time, also in motion. It is pure maths: float only, no static data, no I/O, no clock; each MotionProfile_advance assumes exactly dt has passed. Long sums are Kahan-compensated so long moves do not drift (E2, E3), and the file refuses to build under -ffast-math.

Runs inany the caller's context. In puldir: plan tick for every axis and group profile, main for init, settings checks and a group's set-up while the group is inactive.

8Flow: one MotionProfile_advance

  1. Done? Return. A finished profile does nothing until it gets a new goal.
    p->done
  2. Age the history. When hist_left reaches 0 the ring has turned over and the replaced settings are forgotten (E32).
    hist_left, hist_acc
  3. Step the trapezoid. Landed: velocity 0. Else land if the rest fits in one step within the step rule (D13), keeping the landing step in v_t for one call (E16). Else aim at the ceiling: 0 when stopping, min(|endless_speed|, settings.speed) when endless, sqrt(dd² + 2·decel·|rem|) − dd toward a target.
    trapezoid · toward · kahan_add
  4. Push the velocity into the ring. Compensated sums; recompute on wrap; track the one-signed run.
    push · recompute
  5. Drain after landing. Zeros enter the ring. Once every tap is zero the sums are set exactly to zero; a one-signed ring's lag may only shrink (E30).
    drain, run
  6. Output. vel = sum / n, pos = p_t − lag, acc = Δvel / dt.
    lag
  7. Finish. n + 1 calls after landing (E4) the profile snaps to its target and is done.
    finish

02Axis API puldir.h · puldir.c

1What it does

puldir.h is the one header applications include: the PulDir struct, the status, mode and refusal enums and every PulDir_* call. puldir.c is the main-context half of an axis: init with the conversion, pins, the setters of speed, acceleration, deceleration and jerk, the motion commands and the getters. Speed and the two ramps are what a move uses (a short move never reaches the speed); jerk is a bound the filtered motion stays under (an ordinary move peaks near half of it, E31). Each command checks its arguments, then under port_lock stores a request bit and whatever the caller may read back at once: the mode, the target, isMoving, the enable pin (D17). It never runs the generator; the next plan tick applies the request.

Runs inmain every call. puldir_halt_locked also runs in the plan tick.

8Flow: STM32 start and one IRQ

  1. Attach. Each attach call hands its period to the library and keeps the timer only if it is accepted.
    PulDir_stm32_attachPulseTimer · puldir_timing_pulse
  2. port_start. Both timers attached or Error_Handler; store the callbacks; set both periods with the counter one count before its update; start the pulse timer, then the plan timer. Each plan tick then follows a latch tick by the start skew (E26).
    set_period · HAL_TIM_Base_Start_IT
  3. IRQ entry. Return if UIF is clear (the vector's other source); clear UIF; call the tick with late; set late if UIF came back during the tick.
    PulDir_stm32_pulseIrq
  4. Lock. NVIC disable both IRQs, DSB, ISB; unlock enables plan, then pulse. A tick due inside fires on unlock, late by the lock's length.
    port_lock · port_unlock

12Flows

The same pattern repeats for every feature: main stores a request under the lock, the plan tick acts on it at its next run, and the pulse tick knows nothing about features at all. The flows of each module are in its own tab; these three cross every context.

aA move, end to end

PulDir_moveTo(&ax, 10.0f), from the call until the log says it landed. Time runs down the page. Steps 5 to 9 repeat every plan tick for as long as the move lasts, and step 9 runs N = 50 times per plan tick.

bOne plan tick, in order

puldir_plan_tick() in puldir_plan.c, once every plan_us. Red marks the locked sections; the snapshot lock is the only one every tick takes.

  1. Timing set? Without it there is no axis; return.
    puldir_timing.set
  2. Read the fault pins, with the tick, before the lock on purpose: a pin read can be preempted by pulse ticks, and one landing between the snapshot and the publish would make the prediction stale.
    PulDir_ticks · puldir_fault_sample
  3. Snapshot every axis at one instant. Under one lock: ahead = left % N, the ticks the live increments still run (0 at a boundary, E11), now, and each axis's predicted position Pb = P + inc × ahead, count, live inc, pin direction and pulse-pin level.
    port_lock · puldir_left · puldir_pulse_read · port_unlock
  4. Service each axis, group members too: the enable delay and deferred disable, then the fault input. A latch fails a homing run, holds release and, under the lock, halts the axis or its whole group, then re-reads their snapshots.
    service · puldir_enable_service · puldir_fault_service · puldir_home_fault · puldir_enable_hold · puldir_group_halt · puldir_halt_locked
  5. Groups first. Each active group waits for its members' directions and enable delays, advances its path s and writes every member's increment.
    puldir_group_tick · run_group · MotionProfile_advance(&g->s)
  6. Each other axis: re-base. The generator's origin moves to the whole pulses emitted, so its floats stay small however far the axis has gone (D2).
    run_axis · MotionProfile_rebase
  7. Apply main's requests: halt first, then stream begin, settings, datum, stream end or timeout, target or jog, stop, homing start.
    puldir_halt_generator · puldir_stream_begin · setSettings · puldir_stream_check · setTarget · setEndless · stop · puldir_home_begin
  8. Run the mode. A drive inside its enable delay publishes zero. PROFILE and STOPPING advance the generator; STREAM computes feedforward plus catch-up; HOMING runs its phase; IDLE publishes zero.
    puldir_enable_delaying · run_profile · puldir_stream_run · puldir_home_run
  9. Turn position into an increment. Δ = end − Pb in 32.32; inc = Δ / N truncated. Near the target the end is held M = N² short (D6) until arrival, when the final inc is rounded away so the last edge lands on the interval's last tick (E13).
    puldir_steer · puldir_set_inc · puldir_div_trunc · div_away
  10. Settle and finish. Two runs after arrival, with the pulse pin low and no live increment, the axis goes IDLE, moving clears and EV_LANDED is set (D19).
    run_profile
  11. Release. For every axis, group members included: arm or run auto-release.
    puldir_enable_release
  12. Publish, due at now + ahead. One index flip makes the new set visible. The pulse tick takes it at the next boundary, or at once if it arrives after that boundary (a late set, counted by PulDir_lateSets, E29).
    puldir_publish

cOne pulse tick, per axis

puldir_pulse_tick() in puldir_pulse.c, once every pulse_us. It makes no decisions beyond this chart. Because |inc| is below half a pulse per tick, a pulse is always one tick high and at least one tick low.

13Glossary

Terms a reader meets in the code, its comments and the decision record. A D or E number points at the plan's decisions and execution record.

Ticks and timing
pulse tick
The highest-priority timer interrupt, once every pulse_us, in puldir_pulse.c. It latches increments and writes the PUL and DIR pins; integer maths only.
plan tick
The second timer interrupt, once every plan_us, in puldir_plan.c. It turns requests into increments; all float maths runs here.
N
Pulse ticks per plan interval, plan_us / pulse_us, 2 to 4096; 50 at the README timing. puldir_timing.ticks_per_plan, or PULDIR_TICKS_PER_PLAN in the 32.32 maths. E27
interval
The N pulse ticks between two boundaries. One published increment set runs for one interval. D5
boundary
The tick where left == N: a pending set latches there, so every interval is exactly N ticks. D5, E9, E11
The increment handoff
shadow set
The unpublished one of the two increment sets, which the plan tick fills (puldir_shadow). D5
publish
puldir_publish(due): store the set's due tick, then flip one index so the shadow becomes the published set. No lock is needed between the ticks. D5
latch
The pulse tick copying the whole published set into its live increments, at a boundary or on the first tick at or past the due tick. Every axis switches on the same tick. D5
late set (PulDir_lateSets)
A set that latched after its boundary because the plan tick published too late. It runs the rest of its interval and the next tick corrects the shortfall; the count is logged as plan tick late, total N. E29
Positions
increment (inc)
How far an axis advances per pulse tick, an int32_t in units of 2-32 pulse. At most PULDIR_INC_MAX, just under half a pulse per tick.
2-32 pulse
The unit of the fractional part: PULDIR_ONE (232) of them make one pulse.
32.32 position
A 64-bit fixed-point position, 32 bits of whole pulses and 32 of fraction. Targets and the pulse tick's position use it; unsigned, so wrap is defined. E9
whole-pulse target
moveTo, moveBy and group moves round targets with roundf(x × pulses_per_unit), so a move ends exactly on an integer count and group members can end on one tick. Stops, jogs and streams are not rounded. D4
re-base
Each plan tick shifts the generator's origin to the whole pulses emitted, by the same integer for pos and p_t, so its floats stay small. It shifts, never re-syncs, so the lag carries into the next interval. D1, D2
snapshot
Every axis's pulse state (PulDirSnap) read under one lock at the start of a plan tick, so all axes and groups plan from the same instant. D5
Pb
The snapshot's position predicted at the next boundary, P + inc × ahead with ahead = left % N: where the pulses will be when the new set takes over. D5, E11
The generator
trapezoid
The generator's inner motion: velocity ramps up at accel, cruises at speed if the move is long enough to reach it, and ramps down at decel, computed one step at a time.
ceiling
The highest speed from which the trapezoid can still stop on the target with discrete steps: sqrt(dd² + 2·decel·|rem|) − dd, dd = decel·dt. The code warns not to simplify it.
landing
The step on which the trapezoid covers the rest of the way exactly, when it is at most decel·dt² and within the step rule. The landing step stays in v_t for one call. D13, E16
drain
After landing, zeros enter the jerk filter until the ring is empty; the output keeps moving until then. done comes n + 1 calls after landing. E4, E30
jerk window (n)
The moving-average length, ceil(2·max(accel, decel) / (jerk·dt)), at most MOTION_PROFILE_MAX_TAPS. Twice the larger ramp, because a reversal puts both signs one window apart; so an ordinary move peaks near half the jerk setting. E31
frozen window
While a profile is in flight its window length cannot change; new settings must still be bounded by it, or they are refused (MOTION_SETTINGS_WINDOW, R_WINDOW).
retained history
For n calls after the settings change in flight the ring still holds motion made under the old ones; hist_acc and hist_left keep that acceleration so the next check counts it. E32
Arrival
D6 hold
Near the target, the published end is held M = N² units short until arrival, so the arrival interval moves more than N(N−1) units and its edge lands on its last tick. D6
arrival
The first plan run where the generator has landed with its end on the target: the final increment is published, rounded away from zero. E13
settle
The two plan runs after arrival (settle = 2); they steer again if the count would end short. The axis goes IDLE once settled, done and the pin is low. E13, D19
Edges and counts
edge
The 32.32 position of the next pulse in the current direction, (count + dir) << 32. The pulse tick keeps past, the position minus the edge, so the test is one sign check. D3
hysteresis
Moving up, a pulse fires when the position reaches the next whole pulse above; moving down, when it reaches the next one below. Edges fall at whole-pulse crossings both ways, and dithering around one emits nothing. D3
count
The signed number of edges emitted. PulDir_position reads it: what the drive has been told, not the profile. D18
datum
The position the count is set to by PulDir_setPosition or a finished homing run, with the position and edge moved together under the lock. D18, E29
Commands and answers
request bits
The REQ_ bits main sets under the lock; the next plan tick applies them. Keeps every locked section to a few stores. D17
refusal
A call that says no returns false, changes nothing and stores a PulDirRefusal for PulDir_loop to log. Calls refuse, never clamp. D16
event
A PULDIR_EV_ bit in PulDir.events, set by the plan tick or a refusal, taken and logged by PulDir_loop.
Settings
rate cap
(tick_hz / 2) / pulses_per_unit: speeds at or above it are refused. 25,000 pulses/s at a 20 µs pulse. D7
catch-up time
How fast a stream closes its error: v = sp_vel + err × 1000 / catchup_ms. Default 50 ms; at least five plan intervals. D11, E18
stream timeout
PULDIR_STREAM_TIMEOUT_MS (100 ms) without a setpoint: the axis leaves STREAM and stops at its decel.
debounce
The alarm input must read active for PULDIR_FAULT_DEBOUNCE_MS (2 ms) of plan-tick samples before the latch closes.
clear pulse
The PULDIR_FAULT_CLEAR_MS (10 ms) pulse PulDir_clearFault sends; the latch then lifts on the first inactive sample. E22
enable delay
enable_ms from setDelays: after a drive is enabled, its axis publishes zero this long. E20
release delay
release_ms: with auto-release on, how long an axis stays IDLE before its enable pin is lowered.
fault hold
PulDirEnable.fault_hold: a fault latch halted the axis, so auto-release skips it until its next accepted command. The drive stays enabled. D12, E22
Groups
path profile s
A group's own MotionProfile, from 0 to 1. Member i aims at start + delta × s, so every member arrives on the same interval. Its settings are the members' own over their travels, the smallest winning. E19, E21
