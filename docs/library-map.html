puldir Library Map

puldir drives several PUL/DIR motor drives from one microcontroller. Every pulse comes from a timer interrupt; the main loop only sends commands and reads state. This page shows which file does what, what each struct holds, and how a command travels from your code to a pulse on the wire.

01Three contexts, data moving down

Everything in puldir runs in one of three places. Your main loop calls the API. A 1 kHz timer interrupt, the plan tick, does all the maths. A 50 kHz timer interrupt, the pulse tick, only adds integers and toggles pins. Commands flow down, measurements flow back up, and each crossing has one fixed mechanism. Click a file box to jump to it.

main context, lowest priorityplan tick · plan timer IRQpulse tick · pulse timer IRQ, highesthardwarecall in the same contextcrosses a context

Main context

your loop · any rate · lowest priority

  • Setup: attach both timers, attach the logger, init each axis with its conversion, then pins, limits, register, start.
  • Commands check their arguments, then store a request bit under the lock. They never run the generator.
  • Getters read one value under the lock.
  • PulDir_loop prints what happened. Calling it often or never changes no motion.

Plan tick

Plan timer (TIM7, say) · plan_us = 1000, a 1 kHz tick · below the pulse tick

  • Reads fault pins, snapshots every axis, services faults, enable delay and release.
  • Applies requests, advances each profile, stream, group or homing phase.
  • Publishes one fixed-point increment and direction per axis.
  • All float maths lives here.

Pulse tick

Pulse timer (TIM6, say) · pulse_us = 20, a 50 kHz tick · highest priority

  • Latches a new increment set only at a boundary.
  • Per axis: lowers last tick's pulse, writes a direction change on an edge-free tick, adds the increment, raises a pulse at each whole-pulse crossing.
  • Integer only, about 20 cycles per axis. A pulse is one tick wide (20 µs).

PulDirInc puldir_internal.h

One axis's order for the next interval: inc, how far to advance per pulse tick in units of 2-32 pulse, and dir. A non-zero inc always has the sign of its dir.

written into the shadow setlatched at the boundary

PulDirSnap puldir_internal.h

One axis frozen at the plan tick's instant: Pb, the position predicted at the next boundary, plus count, live inc, pin direction and whether the pulse pin is high. Every axis is taken under one lock, so groups and axes plan from one moment.

PulDirMode enum · puldir.h

Who steers the axis: IDLE, PROFILE (its own target or jog), STOPPING, STREAM, GROUP, HOMING. Main sets it at once when it accepts a command; the plan tick returns it to IDLE at the end.

PulDirStatus enum · puldir.h

The coarse answer: IDLE (drive released), ENABLED, MOVING, FAULT. Computed on demand from the flags, fault first. An axis without an enable pin always counts as enabled.

PulDirHomeState enum · puldir_homing.h

The homing phase, as in cFlexyStepper: toward the switch, pause, back off at 0.2×, pause, adjust, pause, set the datum. ERROR marks a failed run; the failed phase is kept for the log.

PulDirRefusal enum · puldir.h

Why a call said no: FAULT, MODE, ARG, RATE, WINDOW, TAPS, NOT_IDLE, NO_PIN, NO_HOMING, DROPPED, BUSY, FULL. Calls refuse, never clamp; PulDir_loop logs the reason.

REQ_* bits enum · puldir_internal.h

What main asks the plan tick to do: LIMITS, TARGET, ENDLESS, STOP, HALT, SETPOS, STREAM_BEGIN, HOME. A newer motion request replaces an older pending one; the plan tick applies halt first. GROUP_REQ_STOP is the group's one request.

PULDIR_EV_* bits enum · puldir_internal.h

What tells main something happened: REFUSED, LANDED, STREAM_TIMEOUT, HOMED, HOME_FAILED, FAULT, FAULT_CLEARED. Set by the plan tick and by refusing calls; taken and logged by PulDir_loop.

puldir_pin_t port/stm32 · test

On STM32 a GPIO port plus a pin mask, all one BSRR store needs. In the host tests a pin number into the fake port's array. The include path picks the platform.

04A move, end to end

PulDir_moveTo(&ax, 10.0f), from the call until the log says it landed. Time runs down the page. Steps 5 to 9 repeat once per millisecond for as long as the move lasts, and step 9 runs 50 times per millisecond.

05One plan tick, in order

puldir_plan_tick() in puldir_plan.c, once per millisecond. Steps 1 to 3 are the same for every axis; step 5 is per axis. Red marks the only locked section.

  1. Read the fault pins. Done before the lock on purpose: a pin read can be preempted by pulse ticks, and one landing between the snapshot and the publish would make the prediction stale.
    puldir_fault_sample
  2. Snapshot every axis at one instant. Under one lock: how many ticks the live increments still run (ahead = left % N), and each axis's position, count, live inc, pin direction and pulse-pin level.
    port_lock · puldir_left · puldir_pulse_read · port_unlock
  3. Predict the boundary. Pb = P + inc × ahead: where each axis will be when the set published at the end latches. Planning from there lets each new set start exactly where the pulses are.
    PulDirSnap.Pb
  4. Service each axis. Fault debounce (2 ms continuous) and latch, which halts at once; the 10 ms clear pulse; the enable delay. Homing timeouts are not here: the homing run (puldir_home_run) checks them in step 8.
    service · puldir_enable_service · puldir_fault_service · puldir_halt_locked · puldir_group_halt
  5. Groups first. Each group in a move advances its path s and writes every member's increment, once all members' direction pins are set.
    puldir_group_tick · run_group · MotionProfile_advance(&g->s)
  6. Each other axis: re-base. The generator's origin moves to the whole pulses emitted, so its floats stay small however far the axis has gone. The target is handed over relative to that origin.
    run_axis · MotionProfile_rebase
  7. Apply main's requests, halt first, then stream begin, limits, datum, stream end or timeout, target or jog, stop, homing start.
    puldir_halt_generator · puldir_stream_begin · setLimits · puldir_stream_check · setTarget · setEndless · stop · puldir_home_begin
  8. Run the mode. PROFILE and STOPPING advance the generator; STREAM computes feedforward plus catch-up; HOMING runs its phase; IDLE publishes zero. A drive still inside its enable delay publishes zero.
    run_profile · puldir_stream_run · puldir_home_run
  9. Turn position into an increment. Δ = end − Pb in 32.32; inc = Δ / N truncated. Near the target the end is held a hair short (D6) until arrival, when the final inc is rounded away so the last edge lands on the interval's last tick.
    puldir_steer · puldir_set_inc · puldir_div_trunc · div_away
  10. Settle and finish. Two runs after arrival, with the pulse pin low, the axis goes IDLE, moving clears and EV_LANDED is set. Auto-release starts its timer.
    run_profile · puldir_enable_release
  11. Publish. One index flip makes the new set visible. The pulse tick takes it at the next boundary, or at once if it arrives after that boundary (a late set, counted by PulDir_lateSets).
    puldir_publish

06One pulse tick, per axis

puldir_pulse_tick() in puldir_pulse.c, 50,000 times a second. It makes no decisions beyond this chart. Because |inc| is below half a pulse per tick, a pulse is always one tick high and at least one tick low.

07The other flows

The same pattern repeats for every feature: main stores a request under the lock, the plan tick acts on it next millisecond, and the pulse tick knows nothing about features at all.

Setup

The order the library requires. Init and register refuse, and log why, when a step before them is missing.

  1. mainPulDir_stm32_attachPulseTimer(&htim, irqn, pulse_us) and attachPlanTimer(..., plan_us): two timers counting at 1 MHz. The periods are arguments, in µs.
  2. mainPulDir_attachLogger(fn), so init can report.
  3. mainPulDir_init(&ax, "tilt", 280.0f) takes the conversion, fixes the timing and logs max speed 89.2857 units/s, resolution 0.0036 units/pulse. It refuses without both timers.
  4. mainPins, setDefaults, setDelays, homing, then PulDir_register; groups after the axes.
  5. mainPulDir_start writes both timer periods (count − 1) and starts them in step. From here the ticks run.

Jog, stop and halt

Ramped versus immediate.

  1. mainPulDir_jog(&ax, v) stores REQ_ENDLESS and the speed. The position counter is never reset. jog(0) is a stop.
  2. mainPulDir_stop stores REQ_STOP, mode STOPPING. The plan tick ramps down at decel and jerk.
  3. mainPulDir_halt calls puldir_kill under the lock: live and published increments go to zero, so no pulse follows the tick it is called in.
  4. planpuldir_halt_generator rests the profile where the pulses stopped; target = position.

Stream mode

Follow setpoints from your own planner.

  1. mainPulDir_streamBegin: mode STREAM, the current velocity is kept.
  2. mainPulDir_stream(pos, vel) stores one setpoint and its arrival tick. One lock, four stores.
  3. planpuldir_stream_run holds the setpoint to the boundary, then v = vel + error / 50 ms, clamped to the speed limit.
  4. planNo setpoint for 100 ms: leave_stream seeds the generator and stops at decel; EV_STREAM_TIMEOUT.
  5. mainPulDir_streamEnd restores the defaults and stops the same way.

Group move

Straight line in joint space, one final tick.

  1. mainPulDirGroup_moveTo checks every member is idle, rounds each travel to whole pulses (at most 224) and builds the path limits: each member's limit over its travel, tightest wins.
  2. mainUnder one lock all members go to GROUP mode.
  3. planrun_group waits until every member's direction pin is set, then advances s from 0 to 1.
  4. planMember i aims at start + Δi·s; puldir_steer per member.
  5. pulseAll members arrive on the same interval, so every final edge falls on the same tick.

Homing

The cFlexyStepper phases, run from the plan tick.

  1. mainPulDir_homeStart (IDLE, configured) saves the limits and stores REQ_HOME.
  2. planJog toward the switch at the homing speed until the switch byte reads 1; pause 1 s.
  3. planBack off at 0.2× until it reads 0; pause; move by the adjust distance at the defaults; pause.
  4. planDatum = zero position via puldir_set_datum, homed, EV_HOMED.
  5. planA phase timeout halts, sets ERROR, restores the saved limits; EV_HOME_FAILED.

Fault

Nothing that stops a drive depends on the main loop.

  1. planThe ALM pin is read every millisecond. Active for 2 ms continuously: latch.
  2. planpuldir_halt_locked (the whole group if the axis is a member), homed cleared, fault count +1, EV_FAULT. The drive stays enabled (D12) and auto-release is suppressed.
  3. mainMotion commands are refused while latched.
  4. mainPulDir_clearFault raises the clear pin; the plan tick lowers it after 10 ms.
  5. planThe latch drops once the alarm input reads inactive; EV_FAULT_CLEARED.

Enable and release

Per axis, set with PulDir_setDelays.

  1. mainAny accepted motion command on a disabled drive sets ENA active at once (puldir_enable_wake).
  2. planThe axis publishes zero until enable_ms has passed, then starts.
  3. planWith auto-release on, puldir_enable_release sets ENA inactive release_ms after the axis goes IDLE. A new command cancels it; a fault never releases.
  4. mainPulDir_enable(false) during motion halts first.

08From user units to a pulse

A position changes representation four times on its way to the pin. Each step exists to keep precision or speed where it is needed.

user units

float · your degrees, mm

PulDir_moveTo(&ax, 10.0f). Limits are set in the same units.

main

whole pulses

roundf(x × conv)

Targets are whole pulses (D4), so a move ends exactly on an integer count. Limits are kept in pulses too.

main

32.32 target

uint64 · 2-32 pulse

PulDir.target. Unsigned, so wrap is defined.

main plan

profile pulses

float · relative to origin

The generator works near zero: re-based on the emitted count every millisecond, so float32 never loses precision.

plan

increment

int32 · 2-32 pulse per tick

inc = Δ / N. Below 231, so under half a pulse per tick: the 25,000 pulses/s ceiling at 50 kHz.

plan pulse

edge

PUL pin · one tick wide

past += inc each tick; a pulse at each whole-pulse crossing; count is what PulDir_position reads.

pulse

The rates are arguments of the timer attach calls, fixed by the first PulDir_init. At pulse_us = 5 (a 200 kHz tick) the pulse is 5 µs and the ceiling just under 100,000 pulses/s; the plan maths does not change.
